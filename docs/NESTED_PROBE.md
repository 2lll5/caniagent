# Nested instruction behavior probe

`npm run probe:nested` is an opt-in behavior probe for roadmap issue #2. It creates a temporary workspace (without initializing a Git repository) for each supported agent, writes unique root and nested instruction markers using that agent's documented instruction filename, runs the agent from the nested directory, and records which markers appear.

Use `npm run probe:nested -- --output=.caniagent/nested-probe.json` to keep the JSON result. The probe uses documented non-interactive entry points: `codex exec --ephemeral --skip-git-repo-check` (needed because the generated workspace has no `.git`), `claude -p`, `gemini -p`, and `opencode run`. Each result also records a redacted `--version` execution so behavior evidence can be tied to the installed agent version without relying on a separately run probe.

Each generated fixture uses fresh 96-bit random challenge suffixes in its root and nested markers, preventing accidental matches with cached output from previous runs. Each result also includes `fixtureSha256`: SHA-256 of a JSON manifest containing the instruction filename and the exact generated root instruction, nested instruction, and README text. The digest changes with the per-run challenge and does not reveal the marker tokens; it only supports integrity checks when the original fixture bytes are retained separately, not proof that the agent loaded them. The classifier accepts only an exact final non-empty stdout line containing one or both distinct markers (space-separated). Embedded marker substrings, duplicate tokens, earlier marker echoes, and markers on separate lines are inconclusive. This reduces prompt/tool-echo false positives but does **not** establish model-response provenance; treat results as provisional until provider-backed evidence is available.

The probe creates a temporary workspace and redirects `HOME`, `USERPROFILE`, `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, Windows `APPDATA`/`LOCALAPPDATA`, and XDG config/data/state/cache paths into its temporary home. It also removes inherited `NODE_OPTIONS` (including case variants) so Node.js preload hooks do not alter CLI behavior. This reduces accidental reuse of developer configuration and sessions, but **is not a filesystem or process sandbox**: an agent may still access external paths through other inherited settings or its own behavior. The fixture is deleted afterward.

Other environment variables, including authentication, proxy settings, and `NODE_EXTRA_CA_CERTS`, remain inherited. Saved CLI login state in the normal home is generally not reused; environment-based credentials may still be used. Removing `NODE_OPTIONS` can affect agents that depend on enterprise preload hooks. Running the probe can contact model providers and consume quota when credentials are available.

The child-process capture buffer is 8 MiB rather than Node.js's default 1 MiB, allowing long CLI diagnostics before a final marker. Output beyond that limit produces `ENOBUFS` / `spawn_error` and remains `inconclusive`; only the redacted, 12,000-character evidence excerpt is persisted.

A successful process without an eligible terminal marker line is recorded as `inconclusive`, not as evidence that nested instructions are unsupported. Markers in stderr diagnostics are not accepted as behavior evidence. Classification uses the raw stdout in memory **before** redaction and 12,000-character report truncation, so late markers are not lost; raw stdout is never saved separately. Non-zero exits, missing CLIs, timeouts, and signals are also inconclusive. Persisted probe output, including version output, is redacted with the shared probe redactor. Per-run root and nested challenge tokens are additionally replaced with `<ROOT_MARKER>` and `<NESTED_MARKER>` in saved command, stdout, stderr and error fields **before** shared redaction/truncation; only in-memory raw stdout is used to classify markers.

Do not promote a matrix status from a single local run. Record the agent version, platform, and reproducible result before changing compatibility evidence, per `METHODOLOGY.md`.
